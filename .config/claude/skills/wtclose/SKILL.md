# 締め (wtclose)

## Overview

`/wt` の司令塔がセッションを締めるときの手順です。この skill を呼ぶと、frontmatter の Stop hook が登録されます。hook は、司令塔のターンが終わるたびに同梱の検問スクリプト `close_gate.sh` を実行し、締めの条件 P1〜P8 がそろうまでターンを終わらせません(#658)。

検問は、会話の内容ではなく実物(`gh` と `git` の結果、Stop hook の入力、vault の状態ファイル)を見ます。条件がそろうと hook は外れます(`once: true`)。

このセッションの ID は `${CLAUDE_SESSION_ID}` です。検問は、状態ファイルの `session_id` をこの ID と照合して、どの状態ファイルがこの司令塔のものかを見分けます。

| 通過条件 | 検問が見るもの |
|---|---|
| P1 状態ファイルの時点 | 自分の状態ファイルの `as_of` が今日の日付である |
| P2 状態ファイルの大きさ | 200 行を超えていない |
| P3 次の入口 | 「## 次の入口」の節があり、空でない |
| P4 open の PR と残っている worktree | `gh pr list` と `git worktree list` の実物が、全部「## 残っているもの」に理由の種類つきで書いてある |
| P5 裏の待ち受け | Stop hook の入力の `background_tasks` と `session_crons` が空である |
| P6 忘れる候補の一覧 | 検問が一覧を出せた |
| P7 作業物の仕分け | 検問が「最後に辿れた日」の一覧を今回書けた |
| P8 `gh` の失敗 | `gh` が失敗したときは、「PR の状態は未確認」と今日の時刻が書いてある |

置き場は、検問スクリプトが実行時に求めます。司令塔は次のコマンドで確かめられます。

```bash
bash ${CLAUDE_SKILL_DIR}/close_gate.sh --where
```

| 置き場 | 置くもの |
|---|---|
| 記憶 `memory_dir` | 状態ファイル `state_<司令塔の名前>.md` |
| 作業記憶 `workbench_dir` | 指示書・判定表・報告・供養ログ。検問が書く一覧 `_reachability.md` と記録 `_gate_log.jsonl` |

## Steps

### 1. 締めの 4 項目を確かめる

司令塔は、open の PR、残っている worktree、裏の待ち受け、次の入口の 4 項目を確かめる。

**Constraints:**
- **MUST**: open の PR は `gh pr list --state open` で、残っている worktree は `git worktree list` で、実物を確かめる。会話の記憶で埋めない
- **MUST**: 司令塔が作っていない PR と worktree(別のセッションの司令塔が作ったもの、依存を更新する CI が作った PR など)も一覧に出る。司令塔はそれらを消さず、状態ファイルに「別のセッションの管轄」として書く
- **MUST**: 裏の待ち受け(`run_in_background` で仕掛けた `herdr agent wait`、Monitor、ScheduleWakeup や /loop の予約)は、締める前にすべて止める。待ち受けは新しいセッションに引き継がれない。「worker 稼働中」で worktree を残す場合も、待ち受けは止める
- **MUST**: 次の入口(次のセッションの司令塔が最初にすること)を決める

### 2. 作業物を仕分ける

司令塔は、このセッションで生まれた作業物(指示書・判定表・報告・供養ログ)と途中経過を、次の 4 つの行き先に仕分ける。

| 行き先 | 置くもの |
|---|---|
| 状態ファイル | 今どうなっているかと次の入口 |
| セッションノート | 人間と共有する判断・設計・学び(session-log skill) |
| 通常のメモリか Issue | 長く使う事実、再発しうる知見 |
| 上の 3 つから参照されている作業物 | 次のセッションでも読む指示書・判定表など |

**Constraints:**
- **MUST**: どの行き先にも当たらない途中経過は残さない
- **MUST**: 次のセッションでも読む作業物は、状態ファイル・セッションノート・メモリのどれかからリンクする。検問が辿るリンクは、wikilink(`[[ファイル名]]` か frontmatter の `name`)・markdown の相対リンク・絶対パス(`~/` と `$HOME/` の書き方を含む)の 3 種類である。どこからも辿れない作業物は、検問が「忘れる候補」として日数を数え始める
- **MUST NOT**: 司令塔は作業物を別のフォルダへ移さない。メモリや起動プロンプトが絶対パスで参照している
- **MUST NOT**: この手順で作業物を消さない。消す操作は、手順 4 で検問が出す忘れる候補の一覧にユーザーが OK を出した後に行う

### 3. 状態ファイルを上書きする

司令塔は、状態ファイルを上書きする。状態ファイルは、今どうなっているかと次の入口だけを書く 1 枚のファイルで、司令塔 1 体に 1 枚ある。書式は下記「状態ファイルの書式」に従う。

**Constraints:**
- **MUST**: いつの時点の状態かを `as_of` に必ず書く
- **MUST**: 上書きする。経過を追記しない(経過はセッションノートと Issue に書く)
- **MUST**: 残っている PR と worktree は、1 件ずつ理由の種類を付けて書く。種類は「マージ待ち」「レビュー待ち」「worker 稼働中」「別のセッションの管轄」の 4 つから選ぶ
- **MUST**: 記憶の索引 `MEMORY.md` には、状態ファイルへの 1 行だけを置く(例: `- [状態: commander-<repo名>](state_commander-<repo名>.md) — 2026-10-04 18:30 時点の状態と次の入口`)
- **SHOULD**: 200 行を超えないようにする。超えた部分は、セッションノートかメモリに移してリンクする

### 4. 検問を通す

司令塔がターンを終えると、検問が走る。司令塔は、ターンを終える前に次のコマンドで条件を試せる(試し打ちは、8 回の続行の上限を使わない)。

```bash
bash ${CLAUDE_SKILL_DIR}/close_gate.sh --check --session ${CLAUDE_SESSION_ID}
```

**Constraints:**
- **SHOULD**: ターンを終える前に `--check` で試し、そろっていない条件を先に直す。`--check` は P5(裏の待ち受け)を確かめないので、P5 は手順 1 で自分で確かめる
- **MUST**: 検問が止めた場合、stderr には、そろっていない条件の全部が「何がそろっていないか」と「何を書けば通るか」の組で並ぶ。司令塔は 1 件ずつではなく、全部を直してからターンを終える
- **MUST**: Claude Code は Stop hook が 8 回続けてターンを続行させると、次のブロックを無視してターンを終える。同じ状態のまま終了を繰り返さない。直せない条件があれば、ユーザーに状況を報告して判断を仰ぐ
- **MUST**: 検問を通過したら、司令塔はユーザーに、/compact で続けずに新しいセッションで続けることを勧める
- **MUST**: 検問が出す一覧 `<workbench_dir>/_reachability.md` の「忘れる候補」と「古い状態ファイル」を、司令塔はユーザーに見せる。ユーザーが OK を出したものだけを、次のターン以降に司令塔が消す
- **MUST NOT**: 忘れる候補と古い状態ファイルを、ユーザーの OK なしに消さない。検問自身は何も消さない

### 5. 再開を跨いだら呼び直す

検問の hook は、Claude Code のプロセスの中だけに登録される。`--resume` や `--continue` で再開すると、hook は残らない。

**Constraints:**
- **MUST**: 再開した後に締めるときは、`wtclose` を呼び直す

## 状態ファイルの書式

置き場は記憶のディレクトリ(`--where` の `memory_dir`)で、名前は `state_<司令塔の名前>.md` である。司令塔の名前は、`/wt` の手順 3 で名乗った名前(例: `commander-<repo名>`、`commander-<repo名>-2`)を使う。

```markdown
---
name: state-commander-example
description: "commander-example の状態(2026-10-04 18:30 時点)"
type: agent-memory
kind: state
session_id: ${CLAUDE_SESSION_ID}
as_of: 2026-10-04 18:30
---

# 司令塔の状態(commander-example)

## 稼働中の worker

- claude-feat-x(pane w1:p2、worktree /home/user/.herdr/worktrees/example/feat-x、指示書 ~/Documents/Obsidian/AgentMemory/workbench/example/20261004-brief-feat-x.md、待っているもの: CI)

## 判定の途中

- PR #663 のレビュー: 2 件目の指摘まで判定済み。残りは 3 件目

## ユーザー待ち

- 忘れる候補 3 件を消してよいか

## 残っているもの

- [マージ待ち] PR #663 CI が通ったらマージする
- [worker 稼働中] worktree /home/user/.herdr/worktrees/example/feat-x
- [別のセッションの管轄] PR #664 依存を更新する CI の PR

## 次の入口

- 新しいセッションで PR #663 のマージ可否を判定する
```

**Constraints:**
- **MUST**: `session_id` には、このセッションの ID(`${CLAUDE_SESSION_ID}`)をそのまま書く
- **MUST**: `as_of` は `YYYY-MM-DD HH:MM` の形のローカル時刻で書く。P1 は日付の部分が今日であることを求める
- **MUST**: 節の見出しは `## 稼働中の worker`・`## 判定の途中`・`## ユーザー待ち`・`## 残っているもの`・`## 次の入口` の 5 つにする。検問が中身を調べるのは「残っているもの」(P4・P8)と「次の入口」(P3)で、見出しは完全一致で探す
- **MUST**: 「残っているもの」は 1 件を 1 行に書き、行頭の角括弧に理由の種類を書く。PR は `- [種類] PR #番号 補足`、worktree は `- [種類] worktree <絶対パス> 補足` の形にする
- **MUST**: `gh` が失敗して PR の状態を確かめられないときは、「残っているもの」に `- [PR の状態は未確認] YYYY-MM-DD HH:MM 補足` の形で今日の時刻を書く(P8)
- **SHOULD**: 1 つの記憶に複数のリポジトリを束ねている場合は、PR の行にリポジトリの修飾子を付ける(`- [マージ待ち] PR owner/repo#663`)。修飾子を省いた行は、検問が走っているリポジトリの PR として読まれる。他のリポジトリを名指しした行は、検問が実物と照合せず、記録して通す
- **MUST**: 書いてあるのに実物に無い行(マージ済みの PR、消した worktree)は、検問が止めずに記録する。司令塔は記録を見て、終わったものなら行を消す
- **MUST**: `as_of` が 14 日より前の状態ファイルは、検問が根として扱わず、一覧に「古い状態ファイル」として出す。消すのはユーザーの OK の後である

## Troubleshooting

### 検問が 8 回続けて止めて、ターンが打ち切られた
Claude Code は、Stop hook が 8 回続けてターンを続行させると、次のブロックを無視してターンを終える(上限は環境変数 `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` で変えられる)。打ち切られた時点で検問は通過していないので、`once: true` の hook は外れずに残る。司令塔は次のターンで、検問の stderr に並んだ条件を直す。

### gh が通信に失敗する(P8)
検問は、`gh` が失敗したときに PR の状態を確かめられない。この場合、司令塔が状態ファイルに「PR の状態は未確認」と今日の時刻を書けば、検問は通す。作業を進ませることを優先し、誤りは後で記録から巻き戻す。worktree の照合(P4)は、`gh` が失敗しても続ける。

### vault が無い機械や、git リポジトリの外で呼んだ
検問は条件を全部省いて通し、省いた理由を `systemMessage` でユーザーに知らせる。

### 自分の状態ファイルなのに P1 が「無い」と言う
検問は、状態ファイルの `session_id` をこのセッションの ID と照合する。前のセッションの状態ファイルを上書きしたときは、`session_id` を今のセッションの ID に書き換える。
