# 日本語技術記事の文体規範

本文の格を保ちながら、脚注に人格を出す。主張は実録で裏を取る。
この規範は緩急の設計(cognitive-rhythm-writing)と対になる、文体・表記・検証の側の家風である。

## 本文と脚注の役割分担

- **本文は淡々と技術、脚注に人格。** 自分語り・出自・生活感・ネタは本文に書かず、脚注に落とす。本文は主張と根拠の置き場、脚注は人格の置き場。
- 脚注は「読者のツッコミが起きる位置」に置く。本文が疑問を誘発し、脚注が待ち構えて種明かしする構造が理想。
- 例外: 実運用で独立に辿り着いた結論が公式ドキュメント・一次資料と一致したときは、脚注に隠さず引用ブロックで本文に昇格させる。独立一致は「手前味噌ではない」証明であり、記事のクライマックスに使える。
- 脚注を付けるかどうかは、用語のマイナーさではなく**客層との距離 × 記事内の一貫性**で決める。一度「この距離の用語には脚注を付ける」と敷いたら、それより遠い用語を裸で置かない。
- 大物の脚注は「用語解説 → シレっと自分語り → 実物(リポジトリ・設定ファイル)への誘導 → 『また別の記事で』の走りネタ」のフルコース構成が使える(実例: 記憶編 [^8] の Hyprland 脚注)。
- 誘導リンクは深リンク2本立て(全体の入口 + ピンポイントの実物)で「全部漁りたい読者」と「一点だけ見たい読者」を両方拾う。リンクは着地点が実在するか、書く前に確認する。

## 文体・表記

- 一人称は「筆者」で統一する。
- 脚注マーカーの前に半角スペースを入れる(`**正則化** [^1]`)。詰めない。これは記憶編(2026-07)以降の流儀 — それ以前の公開済み記事は詰めスタイルのまま遡及修正しない(記事内の一貫性が優先)。
- 句点なしの短文改行は意図的なタメ(リズム演出)。推敲・校正で勝手に句点を足したり文を結合したりしない。修正提案の対象にもしない。
- CommonMark の flanking rule に注意: `**` の外側が日本語文字に密着していると強調として解釈されない。`**` の前後に半角スペースを入れて回避する。Obsidian のパーサでは描画されてしまうため vault 上では気づけない — 出稿先のプレビューで確認する。

## 実録スタイル

- 実在の PR 番号・Issue・事故・引用のみを使う。**捏造禁止。** 例が必要で実物がないなら、架空であることを明示するか、書かない。
- 実録の数字(件数・日付・密度)は公開直前に一次データから再採取し、「(YYYY-MM-DD時点)」と時点を添える。原稿を寝かせている間に現実の方が進む。
- 「N件ある」と書いたら N 件列挙する。欠けたら一次資料から復元する。
- 外部の状態(Issue の open/close、実装の有無)に依存する記述は、書く前・公開前にその時点の状態を確認する。
- **時間軸を背負う語の精度が実録の信頼性を作る。**「追記」は公開後に足したことを意味する語 — 公開前に書き足した節は「後日談」。読者に見える時間軸と矛盾する語を使わない。

## シリーズ・構成

- タイトルは看板、topics・スラッグは導線。1つの場所に2つの仕事(ブランドと検索)をさせない。ツール名・固有名詞の発見性は topics 側で確保する。
- 続編へのブリッジは時系列ではなく**進化軸**で束ねる。追記素材が複数の続編を指すときは「どの続編の伏線か」で分類し、各軸の末尾を導線にする。
- **先バラシ禁止**: 続編の核心を前の記事の追記で書かない。続編の第1章を既読感で殺さない。
- 唐突な専門用語・概念は「先行実装の紹介」で着地させる(出典・設計思想を示す)。
- 記事間の相互リンクから公開順序の制約を導出する(リンク先が未公開なら 404)。
- 続編は冒頭の `:::message` でシリーズ内の位置(前作リンク)と実録宣言(「登場する事故・PR番号はすべて実物」)を行う。実録宣言は本文の信頼性の前提を最初に張る装置。

## 公開前の点検手順

草稿を仕上げたら、次を機械的に点検する。

1. **生 `**` 検出**: 出稿先プレビューの HTML から `<code>`/`<pre>` を除外し、生の `**` が残っていないか数える。
2. **実録数字の再採取**: 件数・日付を一次データから数え直す。「N件」と列挙数の一致を確認する。
3. **語の時間軸チェック**: 「追記」「先日」「現在」など時間軸を背負う語を拾い、読者に見える公開時間軸と矛盾しないか確認する。
4. **脚注一貫性チェック**: 脚注を付けた用語より客層から遠い用語が裸で残っていないか確認する。
5. **リンク実在チェック**: すべてのリンク・相互リンクの着地点が公開時点で実在するか確認する。
6. **マスク確認**: 勤務先・業務プロダクトの固有名詞が本文・コード片・画像に残っていないか確認する。

## 併用する規範

緩急・認知リズムの設計(文の拍、緊張の管理、駄文の判別)は `../cognitive-rhythm-writing/SKILL.md` に従う。本規範が「何を書くか・どう表記するか」、あちらが「どう読ませるか」を受け持つ。
